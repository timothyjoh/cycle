## Summary

This cycle adds hermetic, execution-based tests for the three fail-fast guard branches of `src/defaults/scripts/verify.sh`, closing the gap left by the prior content-inspection (grep-against-text) tests. The single touched file is `tests/defaults/scripts.test.ts` (+94 lines, now 132 lines total); no production code was modified — `verify.sh` was treated as a read-only reference and confirmed correct by execution.

The change extends the import block (`spawnSync`, `mkdtempSync`/`writeFileSync`/`rmSync`, `tmpdir`, `join`/`resolve`) and adds four module-level helpers below the existing imports, leaving the original five content-inspection tests untouched: `VERIFY_SH` (absolute script path resolved once), `resolveBash()`/`BASH` (resolves an absolute bash path once so a curated empty `PATH` can be passed to the script without making bash itself unlaunchable), `runVerify(seed, env)` (creates a `mkdtempSync` fixture, spawns the real script via `spawnSync(BASH, [VERIFY_SH], { cwd, env, encoding: "utf8", timeout: 30000 })`), and the centralized `assertGuardFired(result, substring)` (asserts `result.error === undefined`, `result.status === 1`, the actionable substring present on stderr and absent from stdout). Three execution-based tests follow, one per guard: the Node guard (a `"test"`-bearing `package.json` with no `node_modules/` ⇒ exit 1 + `npm install` on stderr), the Python guard (`pyproject.toml` under `PATH=""` so `command -v pytest` deterministically fails ⇒ exit 1 + `pytest` on stderr), and the no-runner else branch (empty fixture ⇒ exit 1 + `custom .cycle/scripts/verify.sh` on stderr). Each test removes its tmpdir in a `finally { rmSync(dir, { recursive: true, force: true }) }`. This completes PLAN.md Tasks 1–4; Task 5 (BUILD.md) is this report.

**Deviation from PLAN.md (documented):** PLAN.md assumed all three guards' branch *selection* runs before any external binary, so it routed every test through a single `HERMETIC_ENV` (`PATH=""`). In practice the Node branch's selector is `[ -f package.json ] && grep -q '"test"' package.json`, and `grep` is an external binary — under `PATH=""` it returns "command not found", the `&&` short-circuits, and the script falls through to the no-runner else branch (observed: `grep: command not found` + the no-runner message, the Node guard never firing). I introduced a second env constant `NODE_GUARD_ENV` (`PATH: process.env.PATH`) used only by the Node test; this keeps the test deterministic on any host because the `node_modules`-absent guard still exits before `npm test` is ever reached (npm's presence on PATH is irrelevant), and `grep` is a universal precondition. The Python and no-runner tests keep `HERMETIC_ENV` (`PATH=""`): the Python guard requires `command -v pytest` (a bash builtin) to fail, and the no-runner branch reaches no external tool during selection because `[ -f package.json ]` is false and short-circuits before `grep`.

**Failure modes handled:** wrong exit code / removed-guard regression (`assertGuardFired` requires `status === 1`; an accidental `exit 0` fails the test — the regression this cycle exists to catch); wrong fd (the actionable message landing on stdout is caught by the stdout-must-not-contain assertion); launch failure (`result.error` set or `result.status === null` fails loudly via `assertGuardFired`, and `resolveBash()` throws at module load if bash is unresolvable rather than returning a bogus path); hang (`timeout: 30000` on every spawn); tmpdir residue on assertion failure (`finally` cleanup in each test). Idempotency holds by construction — each test uses a unique `mkdtempSync` directory with no shared mutable state, so an engine retry creates fresh fixtures and leaves no residue. No silently swallowed errors were introduced (no empty catch, no ignored rejection, no discarded non-zero exit).
