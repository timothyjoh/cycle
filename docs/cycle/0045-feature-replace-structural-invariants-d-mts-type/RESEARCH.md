## Open Questions
- **Scoping mechanism for `checkJs`**: the SPEC permits either a per-file directive (e.g. `// @ts-check` at the top of `structural-invariants.mjs`) or a scoped tsconfig include/exclude. A global `compilerOptions.checkJs: true` would newly type-check the five sibling `.mjs` files (`build.mjs`, `check-tsconfig-floor.mjs`, `coverage-gate.mjs`, `gen-cycle-reports.mjs`, `sync-defaults.mjs`), at least two of which use untyped caught-error access (`coverage-gate.mjs:53`, `check-tsconfig-floor.mjs:23`) that strict mode would flag — so a narrow scope is required. The plan must choose the exact mechanism that checks only the target module without regressing siblings. (A `// @ts-check` directive is the most localized option and changes no shared config, but verify it does not alter the module's byte-for-byte runtime/CLI behavior, which is only comment text.)
- **Handling the target module's own untyped-error accesses** (`structural-invariants.mjs:197,199,210,248`): once `checkJs` applies to this file under `strict`, these accesses on `unknown` caught bindings and the `err.exitCode = 2` Error-property assignment will need JSDoc casts/annotations (e.g. typed catch handling or a `@type` cast) to type-check clean. The plan must resolve how to annotate these without changing runtime behavior — the SPEC scopes the change to "co-locating the existing types, not expanding the invariant API," but a clean `checkJs` pass for this file is a hard acceptance gate (`SPEC.md:107`).
- **Type resolution after `.d.mts` removal**: confirm `tsc` resolves the test's `import … from "../../scripts/structural-invariants.mjs"` to the JSDoc-annotated `.mjs` itself (requires the `.mjs` to be type-checked / its types emitted from JSDoc) rather than failing to find a declaration — the planner should verify the chosen `checkJs` scope makes the `.mjs` a valid type source for the importing `.ts` test under `moduleResolution: Bundler` + `allowImportingTsExtensions`.
- **Drift-demonstration for `BUILD.md`** (`SPEC.md:97-104`): the exact temporary edit (e.g. changing the `@returns` to `Promise<string>` or an `Invariant` field type) that should produce a non-zero `npm run typecheck`, then be reverted — to be selected at build time.
