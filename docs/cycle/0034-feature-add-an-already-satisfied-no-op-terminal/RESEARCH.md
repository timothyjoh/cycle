# Research: Cycle 0034

## Cycle Context
SPEC.md asks for a terminal **"already-satisfied / no-op"** cycle resolution that is distinct from failure, detected at the **build phase**. Today, when a `build` or `fix` step exits 0 but produces an empty `git status --porcelain -- src scripts tests`, the engine's empty-diff guard forces `r.status="failed"` (`formatEmptyDiffGuardError`), retries up to `max_cycle_attempts`, lands the issue in `docs/cycle/issues/failed/`, and each terminal failure counts toward `engine.max_consecutive_failures`. The cycle must add: (1) a `NOOP.md` marker check at that guard — when build/fix exits 0, the diff is empty, AND a well-formed `NOOP.md` (recognized reason category ∈ `already-satisfied | duplicate | not-actionable`, ≥1 file:line evidence line) is present, classify the cycle as a no-op (emit `cycle.noop` exactly once + `cycle.end {status:"noop"}`, return a `noop` result); (2) supervisor wiring (`src/cli.ts`) routing the no-op result to the `done/` terminal lane without retrying and without incrementing `consecutiveFailures`/`failedCycles`; (3) prompt edits to `build.md` (and `fix.md`) so the agent emits the marker; (4) completion-proof/`STEP_ARTIFACTS` reconciliation so a no-op build does not trip artifact post-conditions. Marker absent or malformed ⇒ existing `formatEmptyDiffGuardError` failure preserved byte-for-byte. The research-phase early-rejection short-circuit is explicitly **out of scope** (deferred to a sibling cycle).

## Current Codebase State

### Relevant Components
- **Empty-diff guard**: after a `build`/`fix` step exits 0 and its artifact is written, runs `git status --porcelain -- src scripts tests`; empty output ⇒ `r.status="failed"`, `r.exitCode = r.exitCode || 1`, `r.stderr = formatEmptyDiffGuardError(step.name)` — `src/engine/run-cycle.ts:648-663`.
- **`formatEmptyDiffGuardError(stepName)`**: returns ``${stepName} post-condition failed: no code changes detected (step reported ok but git status --porcelain -- src scripts tests is empty)`` — `src/engine/run-cycle.ts:212-214`.
- **Completion-proof contract** (`STEP_ARTIFACTS` table + per-step `step.completion_check`): runs *before* the empty-diff guard, for every step in `STEP_ARTIFACTS`. `build` uses proof `"nonempty"`, `fix` uses `"fix-conditional"` — `src/engine/run-cycle.ts:64-76`, `603-647`. The empty-diff guard runs only `if (r.status === "ok" && (step.name === "build" || step.name === "fix"))` — so a completion-proof failure (empty `BUILD.md`) short-circuits before the empty-diff guard.
- **`cycle.end` emission + return shape**: `cycle.end {status:"failed", failing_step}` returning `{cycleId, artifactDir, status:"failed", failingStep}` at the failure path (`src/engine/run-cycle.ts:729-730`); `cycle.end {status:"ok"}` returning `{cycleId, artifactDir, status:"ok"}` at the success path (`src/engine/run-cycle.ts:734-735`). These two are the only terminal `cycle.end` shapes today.
- **`runCycle` `finally` cleanup**: checkout-base + base-pull, emitting `cycle.checkout` and `cycle.base_pull`; runs for *every* return path including early returns — `src/engine/run-cycle.ts:736-763`.
- **run-one exit-code mapping**: `process.exit(result.status === "ok" ? 0 : 1)` — `src/cli/run-one.ts:92`. A `noop` status would map to exit 1 today (no distinct code). `catch ⇒ process.exit(2)` at `src/cli/run-one.ts:93-95`.
- **Supervisor outcome handling** (`src/cli.ts`): the supervisor spawns run-one as a child (`spawnRunOne`, `src/cli.ts:330-357`), learns the outcome only from the child **exit code** plus `readCycleEndFailure` (a log-tail read). Main loop branches on `exitCode === 0` ⇒ commit + `drainSuccess`; `exitCode !== 0` ⇒ fast-fail/retry/terminal — `src/cli.ts:579-682`. Resume loop is the parallel path — `src/cli.ts:462-490`.
- **`readCycleEndFailure`**: bottom-up log scan for the last `cycle.end {status:"failed"}` for a cycle id; returns `{failingStep, durationMs}`. Only recognizes `status === "failed"` — `src/engine/iteration-guard.ts:14-56`.
- **`commitCycle`**: when `git status --porcelain` shows no changes returns `{status:"skipped", reason:"nothing_to_commit"}` — `src/engine/commit-cycle.ts:175-196`. In the supervisor, only `cr.status === "failed"` routes to retry/terminal; `"ok"` and `"skipped"` both fall to `drainSuccess` (`src/cli.ts:590-619`). So today an empty-diff cycle that somehow reached exit 0 would already drain to `done/` via the `"skipped"` branch.

### Existing Patterns to Follow
- **Terminal-lane move (failure)**: `terminalDrain(cwd, log, todoPath, failedDir, cycleId, issueId, failingStep, failedAttempts)` — stamps frontmatter (`failed_at`/`failed_step`/`failed_attempts`/`last_cycle_id`), renames todo → `failedDir`, calls `drainFailedTerminal`, `propagateBlocked`, emits `queue.drained {outcome:"terminal"}` + `issue.failed`. Has a fallback path when `mutateFrontmatter` throws (writes via tmp+rename, emits `queue.drain_warning`) — `src/engine/issue-lifecycle.ts:9-81`.
- **Success drain**: `drainSuccess` calls `drainOk(cwd, issueId)` (removes the queue row) then `rename(todoPath → doneDir/<issueId>.md)` (tolerates already-moved), emits `queue.drained {outcome:"ok"}` — `src/cli.ts:290-305`. `drainOk` at `src/engine/queue.ts:228-232`. This is the existing path that lands an issue in `docs/cycle/issues/done/`.
- **Retry drain**: `drainFailedRetry(cwd, issueId)` increments `attempt`, sets row back to `pending`, preserves `cycle_id` — `src/engine/queue.ts:234-247`; supervisor helper `drainRetry` at `src/cli.ts:307-317`.
- **Supervisor accounting reset on success**: `consecutiveFailures = 0; failedCycles = []; lastHaltContext = undefined; fastFailKey = null; fastFailCount = 0` — `src/cli.ts:614-618`. The no-op path must mirror this (leave counters untouched / treat like success — SPEC requires no increment and no append).
- **Terminal-failure accounting**: `recordTerminalFailure(prev, opts)` is the single source of truth for incrementing `consecutiveFailures`, appending `failedCycles`, setting `lastHaltContext`, resetting the fast-fail counter, and returning a `{halt}` decision — `src/engine/halt-accounting.ts`; called at `src/cli.ts:595-609`, `648-662`, `668-682`. A no-op must **not** call this.
- **Marker/artifact emptiness classification**: `classifyArtifact(path)` returns `"empty"|"nonempty"` (missing/unreadable/0-byte/whitespace-only ⇒ `"empty"`, fail-closed) — `src/engine/run-cycle.ts:181-188`. This is the shared emptiness primitive a `NOOP.md` reader should reuse for consistency.
- **`STEP_ARTIFACTS` / `ARTIFACT_STEPS`**: single declarative table; `ARTIFACT_STEPS` derived from keys; basenames equal `name.toUpperCase()+".md"` — `src/engine/run-cycle.ts:57-78`. A new artifact like `NOOP.md` does not follow this naming convention (it is not `<step>.md`), so it is not auto-suppressed/auto-checked by this table.
- **Failure handling**: all guards mutate the in-memory `StepResult` (`r.status="failed"`, `r.exitCode = r.exitCode || 1`, `r.stderr = <message>`) and let the unified failure path at `src/engine/run-cycle.ts:720-731` emit `cycle.end` and return — never throw. The empty-diff guard is fail-loud (failure preserved); the SPEC requires any internal error in the marker check to **degrade to the existing failure path** (same fail-closed posture as `classifyArtifact`).
- **Observability**: all engine events go through `log.emit(event, payload)` appended to `.cycle/log.jsonl` (one JSON object per line; `createLogger` at `src/engine/log.ts`, used via `createLogger(repoRoot)` at `src/engine/run-cycle.ts:272`). New events (`cycle.noop`) follow this convention. Exactly-once events are cardinality-pinned with `filter(predicate).length === 1` per CLAUDE.md test conventions; helper `expectExactlyOne(events, eventName)` at `tests/helpers.ts:3`.
- **Idempotency / retry-safety**: `drainFailedRetry` preserves `cycle_id` so retried attempts reuse the same `artifactDir` (the pre-build skip gate reads SPEC/RESEARCH/PLAN left behind). `markInProgress` refuses to overwrite a different in-flight `cycle_id` (`src/engine/queue.ts:210-226`). The single-engine PID lock (`engine-lock.ts`) guards concurrent supervisors. A no-op produces no commit (empty diff), so it is naturally idempotent on the working tree.

## Open Questions
- **Outcome-channel design**: the supervisor learns the cycle result only from run-one's **exit code** (`src/cli/run-one.ts:92`) plus `readCycleEndFailure` (which recognizes only `status:"failed"`). A `noop` status currently maps to exit 1 and is invisible to `readCycleEndFailure`. The planner must choose how the supervisor detects a no-op: a distinct run-one exit code (e.g. 3) consumed by `src/cli.ts`, and/or extending `readCycleEndFailure` (or a sibling reader) to recognize `cycle.end {status:"noop"}`. Both the main loop (`:579-682`) and the resume loop (`:462-490`) must handle it.
- **`ResumeOutcome` / drain plumbing**: whether to add a `"noop"` member to `ResumeOutcome`/`ResumeResult` (`src/cli.ts:37-43`) and a dedicated `drainNoop` helper (analogous to `drainSuccess`) that lands the issue in `done/` while bypassing `recordTerminalFailure` and leaving the accounting counters as success leaves them.
- **Commit interaction**: on a no-op exit, whether the supervisor should still call `commitCycle` (it would return `nothing_to_commit` → `"skipped"`) or skip it entirely. SPEC requires the issue to reach `done/` with a recorded reason and no retry; the existing `commitCycle`→`skipped`→`drainSuccess` chain already reaches `done/` but does not record the no-op reason.
- **`NOOP.md` artifact reconciliation**: whether `NOOP.md` should be added to `STEP_ARTIFACTS`/`ARTIFACT_STEPS` (it breaks the `<step>.md` basename convention) or recognized out-of-band. Note `build`'s `"nonempty"` completion-proof on `BUILD.md` runs *before* the empty-diff guard — the agent must still emit a non-empty `BUILD.md` summary alongside `NOOP.md`, or the completion-proof will fail first (SPEC requires the no-op not to trip the completion-proof check).
- **Marker schema parsing**: the exact validation rule for "≥1 file:line evidence line" and the recognized reason-category set (`already-satisfied | duplicate | not-actionable`) — what regex/format counts as a valid `file:line` line, and where the parser lives (new helper vs inline).
- **`detected_at_step` value source**: confirm it is `step.name` (`"build"` or `"fix"`) at the guard site.
