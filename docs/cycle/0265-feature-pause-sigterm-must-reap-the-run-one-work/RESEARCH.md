# Research: Cycle 0265

## Cycle Context
This cycle turns a signal interruption of a running engine into a clean **suspend-and-resume** rather than a leak-and-halt. Two compounding defects: (1) the supervisor's SIGTERM/SIGINT handler exits the parent but never reaps its `run-one` worker child or that child's `claude` agent grandchild — orphaning a mutating worker after the signal; and (2) the interrupted cycle's partial output dirties the tree, so the next `cycle run` arms `pendingResidueContext` and `haltIfResidue()` fires **before** `runResumeOnce()`, treating WIP as `failed_cycle_dirty_worktree` residue. The fix reaps the worker with a bounded SIGTERM→grace→SIGKILL (mirroring `WALKTHROUGH_KILL_GRACE_MS`) and makes the resume path distinguish *interrupted* (bypass residue halt, no teardown, WIP preserved) from a genuine step-failure (residue guard unchanged, byte-for-byte). Concurrent-run rejection / lock-lifetime is out of scope (landed in cycle 0264).

I documented the full codebase slice — signal handlers (`src/cli.ts:227-242`), `spawnRunOne` (`:446-473`), `runResumeOnce` (`:475-641`), `haltIfResidue` (`:650-695`), the resume-from-tail ordering bug (`:697-753`), `run-one` (no signal handler, `src/cli/run-one.ts:71-98`), the kill-grace pattern (`exec-spawn.ts:71-86`, `walkthrough.ts:22-23`), `log-tail.ts` (no interrupted surface), the arm→persist structural invariant whitelist that covers `src/cli.ts:704`, and the test harnesses in `engine-lock-integration.test.ts`, `resume.test.ts`, and `log-tail.test.ts` — to `docs/cycle/0265-feature-pause-sigterm-must-reap-the-run-one-work/RESEARCH.md`.
