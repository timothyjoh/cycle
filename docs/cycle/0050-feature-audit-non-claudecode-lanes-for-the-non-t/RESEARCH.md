# Research: Cycle 0050

## Cycle Context
SPEC 0050 requires auditing the four non-`claudecode` agent lanes — `gemini`, `opencode`, `pi`, and `auggie` — for the same non-TTY stdin hazard that broke the `codex` lane in cycle 0049 (bare `codex` rejects a piped, non-TTY stdin with `Error: stdin is not a terminal` on codex-cli ≥ 0.136). For each lane the audit must: read its `exec-*.ts` to confirm the prompt-delivery path; check the upstream CLI's actual interactive-mode gating against that path (prioritizing `gemini`, the closest mirror of the codex breakage because it pipes the prompt over stdin); record a per-lane verdict (delivery mechanism + non-TTY-safety confirmation) in `docs/models.md`; and apply a non-interactive-entrypoint fix (mirroring the `codex exec` pattern — `CYCLE_<AGENT>_BIN` override + a build-time structural invariant + lane tests) **only** to a lane where a TTY-gating hazard is confirmed against the upstream CLI. If no lane needs a fix, the source issue gets `expects_code: false` and the doc update is the sole deliverable.

### Existing Patterns to Follow
- **Codex-pattern fix shape** (the canonical reference any applied fix must mirror): prepend the non-interactive subcommand/flag to `argv` as a literal first element, keep the `CYCLE_<AGENT>_BIN ?? "<bin>"` binary resolution, preserve `promptDelivery`, and map `thinking` if the entrypoint supports it — `src/engine/exec-codex.ts:11-21`.
- **Binary-hermeticity convention**: every lane resolves its binary via `process.env.CYCLE_<AGENT>_BIN ?? "<bin>"` so a real CLI on node's prepended bin dir cannot shadow a test fake — present in all five non-claudecode lanes (`exec-gemini.ts:14`, `exec-opencode.ts:15`, `exec-pi.ts:11`, `exec-auggie.ts:10`, `exec-codex.ts:20`).
- **Structural-invariant registration** (`scripts/structural-invariants.mjs`, count-based entries): the codex `exec`-subcommand pin is `{ file: 'src/engine/exec-codex.ts', pattern: /const argv: string\[\] = \["exec"\]/g, expected: 1 }` — `scripts/structural-invariants.mjs:154-159`. Each lane also has a binary-override invariant (gemini `:160-165`, opencode `:166-171`, auggie `:172-177`, pi `:178-183`) and a paired test-hermeticity invariant banning `env: { PATH:` in the lane test (`:188-216`). Any applied fix must add a matching count-based subcommand/flag invariant here.
- **Failure handling** (existing, must be preserved): a lane returns a `StepResult`; non-zero exit ⇒ `{ status: "failed", exitCode, stdout, stderr }` (`exec-spawn.ts:60-64`); spawn `error` (e.g. missing binary / `ENOENT`) ⇒ `{ status: "failed", exitCode: -1, stderr: err.message }` (`exec-spawn.ts:65-67`); timeout ⇒ SIGTERM→SIGKILL process-group kill, result marked `timedOut` (`exec-spawn.ts:71-87`). Each lane additionally wraps the result with `isRateLimitError(r)` → `{ ...r, status: "failed", rateLimited: true }` (`exec-gemini.ts:16`, `exec-opencode.ts:17`, `exec-pi.ts:16`, `exec-auggie.ts:14`, `exec-codex.ts:22`). SPEC §Failure behavior (line 37) requires any applied fix to surface failure through this existing path (non-zero `exitCode`, populated `stderr`), never silently degrade — the `codex exec` behavior is the reference.
- **Observability**: this slice emits no `.cycle/log.jsonl` events of its own — lane results flow up to `run-cycle.ts`, which owns the `step.start`/`step.end` event pairing and rate-limit/retry events. There is no per-lane logging inside `exec-*.ts`.
- **Idempotency / retry-safety**: none at the lane level — each `runStep` is a single pure spawn. Retry/rate-limit/backoff orchestration lives entirely in `run-cycle.ts` (documented in CLAUDE.md). The audit changes do not touch that machinery.
- **`expects_code: false` doc-only path** (the no-fix outcome the SPEC permits): a per-issue YAML-frontmatter boolean, default `true`, read lazily by `resolveExpectsCode` in `run-cycle.ts`; when `false` + empty `src scripts tests` diff + a non-empty in-scope `docs/**` deliverable, the build/fix step stays `ok` and the cycle completes as a normal `ok` (docs committed) — see CLAUDE.md "`expects_code: false` doc-only opt-out". To take this path, add `expects_code: false` to the frontmatter of `docs/cycle/issues/todo/refl-0049-audit-gemini-lane-for-the-same-non-tty-s.md:1-9` (currently no such field) and ensure the only change is `docs/models.md`.

### Test Infrastructure
- **Framework**: Node's built-in `node:test` runner (`npm test`); assertions via `node:assert/strict`. One `tests/engine/exec-<agent>.test.ts` per lane.
- **Conventions / mocking approach**: each test creates temp dirs (`mkdtemp`), writes a fake binary as a `#!/bin/bash` script (`writeFile` + `chmod 0o755`), injects it via `process.env.CYCLE_<AGENT>_BIN` (an **absolute path**, never a PATH stub — hermeticity), invokes `resolveAgent("<agent>").runStep({...})`, and asserts on `status`/`exitCode`/`stdout`/`stderr`, deleting the env var in `finally` — pattern in `tests/engine/exec-codex.test.ts:15-41`.
- **Subcommand-presence test (the model for any applied fix)**: the codex "--model flag in argv" test uses a fake that `echo "$@"` and asserts `assert.match(r.stdout, /^exec\b/)` ("must use the `exec` subcommand, not bare `codex`") and `assert.doesNotMatch(r.stdout, /--thinking/)` — `tests/engine/exec-codex.test.ts:70-118` (assertions at `:89` and `:118`). A new lane fix should add an analogous `/^run\b/`- or `/--print/`-style argv assertion.

## Open Questions

Does the gemini CLI accept a piped (non-TTY) stdin as the prompt in non-interactive mode, or does it (like codex ≥ 0.136) gate non-interactive mode on a TTY and/or require a `-p`/`--prompt`/subcommand entrypoint? The plan step must resolve this against the upstream CLI.
- **opencode**: `opencode --help` shows bare `opencode` defaults to the **TUI**, with `opencode run [message..]` as the non-interactive entrypoint, yet the current lane invokes bare `opencode` with the prompt piped to stdin. Does bare `opencode` consume a piped stdin as a prompt at all, or does it require `run` (and is the message delivered as argv/`--command` rather than stdin)? Confirm whether this constitutes a confirmed hazard warranting an `opencode run`-style fix + delivery change.
- **pi**: `pi --help` shows `--print, -p   Non-interactive mode: process prompt and exit`; the current lane invokes bare `pi` (no `--print`) with the prompt over stdin. Confirm whether bare `pi` with piped stdin enters interactive mode (a confirmed hazard) and whether `--print`/`-p` is the correct non-interactive pin, and how `pi --print` expects the prompt (stdin vs `[messages...]` argv vs `@files`).
- **auggie**: the CLI is not installed locally; the lane already uses `--print --instruction-file` (file delivery, no stdin). Confirm from upstream docs that `--print` is auggie's non-interactive entrypoint and that file delivery does not depend on a TTY, to record the one-line safety confirmation.
- **Per-lane outcome routing**: if ≥1 lane is confirmed hazardous (opencode/pi appear likely from local `--help`, pending the delivery-mechanism confirmations above), the cycle is a code+doc change (fix + invariant + tests for each confirmed lane). If, contrary to the local `--help` evidence, all four are confirmed safe on their current paths, the cycle is doc-only with `expects_code: false`. The plan step must pick the branch per the confirmed upstream gating, not on suspicion (SPEC line 31, 37).
