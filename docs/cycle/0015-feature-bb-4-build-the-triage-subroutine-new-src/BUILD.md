## Deviations from SPEC

- **Per-raw agent invocation, not batched.** SPEC §Requirements asks for raw bodies + queue + todo listing to be passed "as a single rendered input block". The implementation in `src/engine/triage.ts` loops over raws and renders one prompt per raw with only that raw in `{{RAWS_BLOCK}}`. Rationale: simpler retry semantics (each raw owns its 3-attempt budget independently) and the agent never sees cross-raw context in one pass. Trade-off: no cross-raw decomposition / dedup inside a single drain.
- **Last-ordering-wins.** Only the last successful raw's `ordering[]` rewrites the queue (`triage.ts:rewriteOrdering` is called once at the end of the pass with `lastOrdering`). Earlier raws' orderings are discarded and any pending rows omitted by the last call land at the tail via `triage.warning { reason: "ordering_omitted" }`. Acceptable for now because BB-4's queue rarely holds more than one pending row at triage time; revisit if multi-raw drops become common.
