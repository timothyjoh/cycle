## Summary

This cycle adds an optional top-level `defaults: { agent, model, thinking }` block to `workflows.yml`, resolved into every workflow `Step` at config-load time inside `loadConfig`, so operators set a run-wide agent/model/thinking once and override per-step while the rest of the engine keeps reading concrete `step.*` values unchanged. All five PLAN.md tasks are complete.

**Files modified/created:**
- `src/engine/exec.ts` (+4 lines): added exported `knownAgents()` accessor returning `Object.keys(REGISTRY)`; `REGISTRY` stays module-private. (Task 1)
- `src/engine/workflow.ts` (+39 lines): imported `knownAgents`; added the `Defaults` type and `defaults?: Defaults` field on `CycleConfig`; added the load-time resolution + validation pass after commit normalization and before `return parsed as CycleConfig` — for every step it resolves `agent = step.agent ?? defaults.agent`, `model = step.model ?? defaults.model`, `thinking = step.thinking ?? defaults.thinking`, validating each resolved agent against `new Set([...knownAgents(), "bash"])`. **Failure modes handled this cycle:** (1) a step with neither `step.agent` nor `defaults.agent` throws a `workflows.yml malformed: workflow "<name>" step "<step>" has no agent and no defaults.agent (<path>)` error; (2) an unknown resolved agent (from default or step) throws `… has unknown agent "<value>" (<path>)` naming the rejected value; (3) a present-but-non-object `defaults` (string or array) throws `… defaults must be an object (<path>)`. All three are raised synchronously out of `loadConfig` (and propagate through `loadWorkflow`/`runCycle`, aborting the cycle at config load before any step runs); none are swallowed. Resolution is a side-effect-free, deterministic in-memory mutation of the freshly-parsed object, so it remains idempotent and safe under engine retry/restart. These paths are covered by the dedicated failure-path tests in `tests/engine/workflow-defaults.test.ts` (cases for missing agent, unknown default agent, unknown step agent, string `defaults`, array `defaults`) and by the two updated `run-cycle` tests asserting `runCycle` rejects with the malformed-config error.

**Deviations from PLAN.md:** PLAN.md described `src/defaults/workflows.yml` and the test fixtures with a simplified shape; the actual repo file carries `base_branch`, `rate_limit_backoff_ms`, `commit.push`, workflow `description`/`max_cycle_attempts`, and different step sequences for `document`/`quickfix`/`e2e-tests`. The implementation preserved all of that and only added the `defaults:` block and dropped redundant `agent:` lines, so the existing `feature-loadable`, `feature-yaml`, and dogfood structural tests still pass unchanged. Not anticipated by PLAN.md: two pre-existing tests (`run-cycle.step-end-stderr-dispatch.test.ts` "failed dispatch step.end carries verbatim UnknownAgentError stderr" and `run-cycle.test.ts` "step with unregistered agent fails the step and ends the cycle") configured an unknown agent in `workflows.yml` and asserted the **runtime** `resolveAgent` fallback in `run-cycle.ts` (the `UnknownAgentError` catch that converts to a failed `StepResult`). The SPEC mandates that unknown agents now fail at **config load**, which fires before dispatch and makes those configs unreachable at runtime. Since the SPEC's acceptance criteria require the load-time throw and changing `run-cycle.ts` step-execution logic is explicitly out of scope, I updated both tests to assert the new contract: `runCycle` now rejects with the load-time malformed-config error naming the workflow, step, and rejected agent. The runtime fallback code in `run-cycle.ts` was left untouched (out of scope) and remains at 100% line coverage.

**Deferred / follow-up notes:** Agent/model/thinking forwarding to the CLIs (sibling issue `feat-agent-model-forwarding`) remains out of scope — this cycle only resolves config values. The runtime `UnknownAgentError` fallback in `run-cycle.ts` is now defense-in-depth that config-driven steps can no longer reach (load-time validation pre-empts it); a future cleanup could remove it, but that is a `run-cycle.ts` change outside this SPEC. The risk PLAN.md flagged — an unknown `defaults.agent` that every step overrides would not throw because it is never inherited — is accepted as harmless (the default is unused) and unchanged.
