# Research: Cycle 0035

## Cycle Context
This cycle adds a **research-phase** no-op short-circuit to the `feature` workflow. Cycle 0034 shipped only the build-phase half of the no-op / already-satisfied resolution: a `build`/`fix` step that exits 0 with an empty `src scripts tests` diff and a valid `NOOP.md` marker resolves the cycle to `cycle.noop` and drains the issue to `done/` without burning the failure budget. SPEC.md asks for a second, earlier detection point: after the `research` step exits 0, the engine reads `NOOP.md` via the existing `classifyNoopMarker` (fail-closed) and, on a **valid marker only**, short-circuits the cycle to the existing `cycle.noop` / `cycle.end { status: "noop" }` terminal outcome (with `detected_at_step` = the research step) before any downstream step runs — reusing the cycle-0034 marker schema, event shapes, and `noopDrain` / run-one exit-code-3 drain path wholesale. The research prompt (`src/defaults/prompts/research.md`) is updated to instruct the agent to emit a conformant `NOOP.md` when it concludes an issue is already satisfied / duplicate / not-actionable. Marker absent/malformed/unreadable ⇒ research continues to the next step exactly as today.

For research (no empty-diff failure to fall back to), an invalid/absent/error marker must simply continue to the next step with no new event (per SPEC §Requirements / §Failure behavior).
- **Observability convention**: all engine events go through `log.emit(event, payload)` into `.cycle/log.jsonl`. No-op events: `cycle.noop { cycle_id, issue_id, reason, detected_at_step }` then `cycle.end { status: "noop" }` — `src/engine/run-cycle.ts:749`–`755`. `queue.drained { outcome: "noop", reason }` — `src/engine/issue-lifecycle.ts:160`.
- **Idempotency / retry-safety**: a `noop` outcome does **not** retry, does **not** increment `consecutive_failures`, does **not** call `commitCycle` (handled by the exit-3 supervisor branches). `noopDrain` mirrors `terminalDrain`'s robust tmp+rename fallback on `mutateFrontmatter` failure (`queue.drain_warning`) — `src/engine/issue-lifecycle.ts:110`–`158`.
