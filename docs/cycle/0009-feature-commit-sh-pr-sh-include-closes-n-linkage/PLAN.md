## Task 2: Add `lib/closes.sh` parser helper + unit tests

### Overview

A single bash function `closes_block` that emits zero or more `Closes #<N>` lines on stdout. Both consumers source this file. Function contract:

```
closes_block <issue_file_path> <owner_slash_repo>
```

Reads the file, extracts every `https://github.com/<owner>/<repo>/issues/<N>` whose `<owner>/<repo>` matches the second arg, deduplicates `<N>` preserving first-occurrence order, strips trailing `)`, `]`, `?…`, `#…`, `.`, `,`, and prints one `Closes #<N>` per line. Empty stdout when no matches.

### Changes Required

**File**: `src/defaults/scripts/lib/closes.sh` (new)
**Changes**:

```bash
#!/usr/bin/env bash
# Helper sourced by commit.sh and pr.sh. Emits `Closes #N` lines for every
# GitHub issue URL in the cycle's issue file that targets the current repo.
# No side effects beyond stdout.

closes_block() {
  local issue_file="${1:?closes_block: issue_file required}"
  local repo_slug="${2:?closes_block: repo_slug required}"
  [ -r "$issue_file" ] || return 0

  awk -v slug="$repo_slug" '
    {
      s = $0
      while (match(s, /https:\/\/github\.com\/[^[:space:]]+\/issues\/[0-9]+/)) {
        url = substr(s, RSTART, RLENGTH)
        s = substr(s, RSTART + RLENGTH)
        # split url: https://github.com/<owner>/<repo>/issues/<N>
        n = split(url, parts, "/")
        if (n >= 7) {
          owner = parts[4]; repo = parts[5]; num = parts[7]
          if (owner "/" repo == slug && num ~ /^[0-9]+$/) print num
        }
      }
    }
  ' "$issue_file" | awk '!seen[$0]++ { print "Closes #" $0 }'
}
```

Notes:
- Regex `[^[:space:]]+/issues/[0-9]+` greedily consumes trailing `)`, `?…`, `#…` etc. into the URL match; the post-`split` step recovers a clean `<N>` because trailing chars never make it into the integer slot — but to be robust we anchor `num ~ /^[0-9]+$/` and let `split` discard anything after the `/`. To guarantee numeric purity, an extra `gsub(/[^0-9].*/, "", num)` line is added before the regex check.
- `awk '!seen[$0]++'` dedupes preserving first-occurrence order — standard idiom.
- Empty file or absent file → returns 0 with no output.

**File**: `tests/defaults/closes-linkage.test.ts` (new) — initial subtests covering the helper directly via `bash -c 'source lib/closes.sh; closes_block …'`. Cases:

1. Single URL matching current repo → one `Closes #99` line.
2. URLs `#7, #9, #7` → exactly `Closes #7\nCloses #9`.
3. URL with trailing `)`, `?ref=x`, `#anchor`, comma → bare `Closes #N`.
4. URL pointing at `other/repo` → no output.
5. Empty issue body → no output.
6. Missing file → no output (and exit 0).
7. URL in YAML frontmatter `title:` field → counted (whole-file scan).

### Success Criteria

### Unit Tests

Two integration scenarios in the same test file:

Engine test in `tests/engine/run-cycle.test.ts` (or equivalent) covers `CYCLE_ISSUE_ID` env injection in isolation — no real cycle run needed; a tiny bash step that `echo "$CYCLE_ISSUE_ID"` and stdout capture suffices.

## Risk Assessment

- **`awk` regex portability across BSD `awk` (macOS) vs GNU `awk` (Linux CI)**: the `match` + `RSTART/RLENGTH` idiom is POSIX awk. Avoid GNU extensions like `gensub` and `\b`. Mitigation: stick to `match` + `substr`, the same constructs already used in `commit.sh:25`.
- **`gh repo view` failure (offline / unauth)**: returns non-zero, `repo_slug` becomes empty, helper emits no lines (matches all-skip semantics). Acceptable degradation — commit/PR still proceed without `Closes` block.
- **Trailing punctuation greedy-matched into URL**: regex `[^[:space:]]+/issues/[0-9]+` ends on the `[0-9]+` boundary; trailing `)` etc. are not part of the match. Verified by Task 2 subtest 3.
- **YAML frontmatter URLs**: whole-file scan picks them up. Acceptable per SPEC ("the cycle's issue body" interpreted as the issue file). Dedup prevents double-counting if the same URL appears in both title and body.
- **`CYCLE_ISSUE_ID` unset for non-issue-driven cycles**: scripts must gracefully skip when unset — guard with `[ -n "${CYCLE_ISSUE_ID:-}" ]`. Verified by empty-case regression test.
- **`.cycle/scripts/` drift mid-cycle on this repo**: the helper file is new — `sync-defaults.mjs` must run after the `src/defaults/scripts/` edits and before re-invoking cycle on this repo. Already a documented step in the script's leading comment.
- **`gh` PATH shim ordering vs Node's `child-env.ts:16-27` PATH prefix**: tests must prepend the shim dir ahead of the Node bin dir. Mitigation: set `PATH=${shim_dir}:${process.env.PATH}` explicitly in `spawnSync` env; do not rely on engine's child-env helper for these direct-script tests.
