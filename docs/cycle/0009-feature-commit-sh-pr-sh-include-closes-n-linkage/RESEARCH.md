# Research: Cycle 0009

## Cycle Context

SPEC.md asks for auto-`Closes #N` linkage in `commit.sh` and `pr.sh`. Both scripts (under `src/defaults/scripts/`) must parse the current cycle's issue body file for `https://github.com/<owner>/<repo>/issues/<N>` URLs whose owner/repo matches the current repo, deduplicate the `<N>` values, and emit one `Closes #<N>` line per match. For `commit.sh` the block appends to the commit message **body** separated from the subject by a blank line. For `pr.sh` the block appends to the PR body passed to `gh pr create`. Cross-repo URLs, PR URLs, and alternate keywords (Fixes/Resolves) are out of scope. When no qualifying URL is present, output must be byte-identical to current behavior. Cycle/issue context is read from the latest `cycle.start` event in `.cycle/log.jsonl`; the issue file lives at `docs/cycle/issues/triaged/<issue_id>.md` (fall back to `queued/`).

## Open Questions

- **Shared parser distribution**: SPEC says "shell helper, used by both `commit.sh` and `pr.sh`". Should it be a new file (e.g. `src/defaults/scripts/lib/closes.sh` sourced by both) or duplicated inline in each script? No precedent for a sourced library under `src/defaults/scripts/`; only three sibling scripts exist today.
- **Where to look for URLs in the issue file**: SPEC says "the cycle's issue body". The frontmatter `title:` field also contains the URL in realistic issues (see queued issue example). Plan must decide whether to scan the whole file or strip frontmatter first. Either choice changes dedup semantics when the same `#N` appears in both title and body.
- **JSON parsing in bash**: `.cycle/log.jsonl` cycle.start line is JSON. `jq` is not currently a documented dependency (only `gh`, `git`, `bash`, `node` per BRIEF.md). `gh` ships with `jq`-like `-q` selectors only on `gh` subcommands, not arbitrary JSON. Plan must pick: rely on `jq`, parse with `awk`/`sed`/bash regex, or have the engine inject `CYCLE_ISSUE_ID` into env (`src/engine/run-cycle.ts:38-43`).
- **PR body template preservation**: SPEC says "PR body keeps existing template/content and appends the block at the end after a blank line." Current body is the literal `"Generated by cycle."` (`src/defaults/scripts/pr.sh:13`) — no template file exists. Planner must confirm whether to retain that string as the leading content or replace it.
- **Where to capture `gh pr create --body` in tests**: no existing PATH-shim harness for `gh`. New test infra (a tiny `gh` stub that logs argv to a file) needs to be designed and placed somewhere — likely under `tests/defaults/_shims/gh` or generated inline per test. Affects `tests/defaults/closes-linkage.test.ts` shape.
- **`DOGFOOD.md`** referenced in SPEC's documentation updates does not exist at repo root (`ls` shows none). Planner must decide whether to create it or treat that bullet as no-op.
- **`AGENTS.md` / `CLAUDE.md` at repo root** also do not exist. SPEC's "if present" qualifier covers this — confirm no-op for the docs step.
